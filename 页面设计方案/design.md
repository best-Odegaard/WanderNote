# WanderNote 行笺 · 页面设计方案 v1.0

> 一句话定位：**「对话即行程」—— 用点击式对话把「模糊的出行念头」补全成「带酒店、带路线、带购票入口的完整行程」，并在出行当天真正用得上。**

---

## 一、为什么重新设计跳转与交互

### 1.1 当前问题（基于现有代码与文档的判断）

| 问题 | 表现 | 设计对策 |
|---|---|---|
| 产品定位不突出 | 首页直接是聊天页，但用户不知道「这和其他 AI / OTA 有什么不同」 | 首屏即「输入框 + 灵感推荐」，用真实城市/景点卡片代替口号说明产品（v1.3 起） |
| 入口分散 | 智能规划、AI 对话、行程导入、探索各走各的，新手无所适从 | 全量入口收敛到「对话」；其余能力作为上下文带入 |
| 状态不可见 | 聊天页不知道还差什么信息才能生成行程 | 增加需求完整度条 + 浮出工具条 |
| 结果页太重 | 行程详情直接铺地图 + 上拉时间轴，第一次看很懵 | 增加「今日模式」单屏页，出行当天只看当前节点 |
| 导航承诺过度 | 「一键导航全天路线」在地图 URI 能力下做不到 | 改为「应用内自绘 + 分段接续导航」 |

### 1.2 设计目标

1. **3 秒看懂产品**：首屏 1 个输入框 + 灵感推荐卡片，让用户立刻能「做一件事」而不是「读一段话」。
2. **3 次点击内出第一版骨架**：目的地 → 天数 → 生成。
3. **80% 回答通过点击完成**：chips 优先，键盘兜底。
4. **出行当天可用**：今日模式、离线可读、一键唤起导航。

## 三、核心交互规则

### 3.1 对话优先首页

- 首屏第一个元素就是对话输入框（不再有顶部口号区）：
  - 占位文案：「例如：肇庆 2 天，亲子，想看落羽杉」
  - 右侧发送按钮
  - 输入即进入 `ai-chat.html`
- **内容排序（v1.3 修订）**：输入框 → **灵感推荐** → 最近行程。
  - 顶部「对话即行程 + 副标题 + 决策/编排/执行 3 个 pill」整块删除：用户反馈该区占屏、信息密度低，愿意用「直接开始」替代「先读一段介绍」；
  - 灵感推荐紧随输入框：用户还没想好去哪儿时，城市/超级景点卡片是最顺的下一步；
  - 最近行程最后：对老用户仍有价值，但不抢占新用户第一眼。
- **定位表达的替代承载**（删掉口号区后的补偿设计）：
  - 输入框 placeholder 直接给出可抄的例句，用「能说出这种需求」隐式表达能力边界；
  - 灵感推荐卡片用真实城市 + 一句话理由（如「肇庆 · 落羽杉季 / 全国最大溶洞群，冬季恒温 20℃」），用具体内容而非抽象词证明「这里能决策」；
  - 「我的 → 关于」保留完整产品介绍，承接需要看长文案的用户。

### 3.2 二级提问系统

- **每轮只问 1 个问题**，带 3-5 个 chips。
- 任何问题可「跳过 / 还没想好」，跳过后用默认值，并在结果中标记。
- **最多 6 轮**自动出结果。
- 已答槽位可用自然语言覆盖（如「改成 3 天」）。
- 底部常驻「✨ 直接生成行程」按钮，不打断追问。
- **新建会话（v1.2 新增）**：对话页右上角常驻「＋ 新会话」按钮。
  - 无进度时直接重开；
  - 已有进度时先二次确认（「将清空当前对话进度与已选需求」），确认后清空槽位与暂存必去项、重置提问轮次，并插入一条系统提示「已开启新会话」。

### 3.3 需求完整度与浮出工具条

```
完整度 = Σ(已填槽位权重) / Σ(全部槽位权重)

destination 25 / days 20 / departCity 10 / dateRange 10
people 10 / budget 10 / hotelStyle 10 / companion 5
```

| 条件 | 浮现入口 |
|---|---|
| destination + days 已填 | 「✨ 生成骨架」常亮 |
| 完整度 ≥ 50% | 🏨 选酒店 |
| 完整度 ≥ 60% 且 departCity 已知 | 🚂 查车票 |
| 完整度 ≥ 60% 且 hotelStyle 已知 | 🗺️ 生成完整路线 |
| 完整度 ≥ 80% | AI 主动提示「信息够了，直接生成？」 |

- 工具条**渐显** + 一次轻震动。
- 已浮现入口不因改答案而消失（只更新状态）。

### 3.4 探索页：从「不知道去哪」到「就它了」

- 顶部城市页签（横向滚动），按近期热点排序。
- 每个城市 1-2 个超级景点大卡：大图 + 一句话理由 + 热点标签。
- 大卡下方三个分区入口：吃 / 玩 / 景点。
- 每个内容卡片右侧有「加入行程」→ **先二次确认，再写入**（见下方规则）。
- 主 CTA：「就这里，帮我规划」。

**「加入行程」确认规则（v1.1 修订）**：

1. 点击「加入行程」**不直接默认加入**，先弹出确认卡片：展示内容名称 + 说明「将作为必去项带入 AI 对话」；
2. 用户点「确认加入」才写入暂存清单（sessionStorage），并以 toast 提示「已加入行程（N）」+ 「去规划 →」快捷入口；
3. 点「再想想」或点击蒙层关闭，不产生任何写入；
4. 多次加入自动去重、计数累加；进入对话页时合并进 `mustVisit` 槽位并清空暂存清单；
5. 首页直接输入 / 智能导入等「新会话」入口会清空暂存清单，避免串场。

### 3.5 行程详情页

- 地图为背景层，上拉框为内容层。
- 上拉框四档：覆盖 3/4 → 1/2 → 1/4 → 只留把手。
- 顶部天标签 + 总览标签。
- 每个节点卡片：时间 + 名称 + 图/emoji + 地址/开放/门票 + 操作（导航 / 调序 / 删除）。
- 底部操作：「今日路线」+「保存行程」。

### 3.6 完整路线 / 接续导航

- 以酒店为起点和终点，画出全天闭环。
- 顶部显示：「第 2/5 段 · 下一站：七星岩」。
- 每段提供：上一段 / 下一段 / 跳过此点 / 一键导航。
- 点击导航 → 弹出地图选择（高德 / 百度 / 腾讯）→ 唤起外部 App。
- 应用内地图自绘完整路线；外部地图只负责单段导航。

### 3.7 今日模式

- 出行当天打开行程，默认进入 `trip-today.html`。
- 单屏显示：当前节点 + 下一段移动 + 预计到达时间。
- 大按钮：「导航去这里」。
- 下拉可查看全天时间轴。

## 五、H5 原型实现说明

### 5.1 技术选型

- 纯静态 HTML5 + CSS3 + 原生 JS，无框架。
- 共享样式：`assets/styles.css`
- 共享脚本：`assets/app.js`（路由辅助、mock 数据、状态管理）
- Mock 数据：`assets/mock.js`
- 页面间使用 `<a href="xxx.html">` 跳转，模拟真实 H5 体验。

### 5.2 Mock 数据范围

- 城市列表：肇庆、重庆、成都、大理、西安
- 每个城市：1 个超级景点 + 吃/玩/景点各 3-5 条
- 酒店列表：每个城市 4 家精选酒店
- 对话状态机：模拟 6 轮二级提问的槽位推进
- 示例行程：肇庆 2 日游（含时间轴、坐标、酒店）

### 5.3 可点击链路

1. 首页输入 → ai-chat.html（开场问「你想玩几天？」）
2. 首页「我的行程」卡片 → trip-detail.html
3. 探索页城市卡 → explore-city.html
4. explore-city「就这里，帮我规划」→ ai-chat.html（携带城市上下文）
5. ai-chat 点击 chips → 下一问 / 生成骨架 → trip-detail.html
6. trip-detail「今日路线」→ trip-route.html
7. trip-detail「选酒店」→ plan-hotel.html
8. plan-hotel「确认这家」→ 返回 trip-detail（酒店更新）
9. trip-route「一键导航」→ 地图选择弹窗
10. profile「登录」→ auth-login.html

## 七、设计原则 checklist

- [ ] 首页首屏 3 秒内让用户能开始操作（输入框立刻可用，不需要先读文案）。
- [ ] 首页顺序为：输入框 → 灵感推荐 → 最近行程（v1.3 已删除顶部口号区）。
- [ ] 对话页有常驻「新建会话」入口，且有进度时二次确认。
- [ ] 所有种草内容都有「加入行程」或「帮我规划」的下一步。
- [ ] 「加入行程」必须经过二次确认，不直接默认写入。
- [ ] AI 对话页每轮只问 1 个问题，带 chips。
- [ ] 完整度条和浮出工具条始终可见。
- [ ] 任何页面都能一键回到对话（悬浮「问小笺」按钮）。
- [ ] 行程详情提供「今日模式」入口。
- [ ] 导航不做「一键导入全天」的过度承诺。
- [ ] 酒店/车票价格统一标注「参考价，以实际为准」。

## 八、待你确认的点

1. **社区定位**：游记社区是作为「内容种草」反哺探索页，还是独立流量入口？当前方案把它放在「我的-我的游记」和首页二级入口。
2. **登录拦截**：哪些动作必须登录（保存行程、发布游记、收藏）？方案默认「生成行程可匿名，保存/发布需登录」。
3. **首页形态**：v1.3 已按反馈删除顶部口号区，第一屏为「输入框 + 灵感推荐」。需要确认的是——品牌名「WanderNote 行笺」与一句 slogan 是否要换一种更轻的承载方式（例如导航栏左侧小字、或仅保留在启动页/关于页），还是首页完全不做品牌露出？
4. **品牌色**：沿用现有薄荷绿（`#14b8a6`）为主色，是否调整？
