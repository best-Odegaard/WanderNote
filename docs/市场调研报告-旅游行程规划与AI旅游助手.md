# 旅游行程规划 / AI 旅游助手 市场调研报告

> 目的：为 WanderNote（行笺）重构提供市场依据，让产品链路更贴近真实用户使用场景，降低使用繁琐度。
> 版本：v1.0　编制日期：2026-02
> 数据说明：报告中所有数字均标注来源与年份；未找到公开数据的结论明确标注「未找到公开数据」，不做推测性填充。

---

## 0. 摘要（TL;DR）

1. **市场机会真实存在**：2025 年前三季度国内出游 49.98 亿人次（同比 +18.0%）、国内游客出游总花费 4.85 万亿元，自由行与短途高频出行成为主流，规划环节的「信息过载」仍是最大未解决问题。
2. **「填表单 → 出方案」正在被淘汰**：海内外头部产品的方向高度一致——**一句话/一张截图进，可执行的行程单出**，并把「生成」升级为「可对话修改 + 可预订 + 可携带」。Wanderlog、Mindtrip、Layla、Google AI Mode、ChatGPT 均在往这个方向收口；国内携程、马蜂窝、飞猪把 AI 助手做成**入口级搜索框**，而不是独立表单页。
3. **用户真正的痛点不是「生成得慢」，而是「不敢信、不能改、出门用不上」**：ACL 2025 Findings 的 TripTailor 基准显示，基于 50 万+ 真实 POI 评估，**最先进 LLM 生成的行程中不到 10% 达到人类水平**；中国青年报调研中 AI 规划的头号缺陷是「**行程缺乏灵活性 54.7%**」；Booking.com 调研中 **42% 的用户「总是核查 AI 内容」**，仅 12% 愿让 AI 独立决策。行业共识痛点集中在**可执行性（executability）**。
4. **决策正在临期化**：2025 国庆 **58.3%** 用户倾向当天预订，青年群体超七成当天订酒店；Klook 调研显示 50% 的行程策划者单次规划耗时 **20 小时以上**，中国内地最大压力源是「协调行程时间 75.8%」——即**时间窗以分钟计、协作是刚需**。
4. **本项目当前链路偏重**：首页 → 规划页（目的地/天数/偏好/人数/预算/出发地）→ 必答问卷 4 题 → AI 对话页再点「生成行程」→ 轮询两阶段生成 → 详情页。要拿到第一份行程，用户需要**跨越 5 个界面、回答 10+ 个问题、至少点击 6 次**，且未登录会被强制跳登录；已知知识库仅 **10 条景点 seed**，未收录城市等于纯 LLM 生成。
5. **重构核心建议**（详见第 9 章）：把「表单前置」改为「**对话即行程**」，用**一段自然语言（或一张截图/一条链接）**完成冷启动；把问卷从「必答」降级为「**对话内嵌选择题、可跳过**」（对标马蜂窝 AI 路书）；补上三块最影响留存的能力——**可改（局部重排/换景点）、可信（真实 POI + 来源标注 + 不确定显式提示）、可携带（今日单屏 + 离线 + 导航 + 语音导览）**。

## 2. 宏观背景

### 2.1 市场规模与结构

- 2025 年前三季度，国内出游人次 **49.98 亿**，同比增长 **18.0%**；国内游客出游总花费 **4.85 万亿元**（[经济日报](http://www.jingjiribao.cn/static/detail.jsp?id=616014)、[光明网](https://m.gmw.cn/2025-10/21/content_1304194326.htm)、[中国政府网](https://app.www.gov.cn/govdata/gov/202510/21/538817/article.html)）。
- 移动互联网大盘：2025 年上半年月活用户 **12.62 亿**，同比增速持续保持 2% 以上，增量来自年轻用户与银发群体（[QuestMobile 2025 全景生态流量半年报告](https://m.jiemian.com/article/13034358.html)）。

**含义**：旅游大盘仍在增长，但流量红利消失，行程规划类产品的竞争点从「拉新」转向「把一次规划变成一次可执行的行程并沉淀复访」。

### 2.2 决策链路六阶段（规划类产品的战场在哪）

```
① 种草（内容平台）→ ② 搜集攻略（多平台跳转）→ ③ 定行程（最痛、最缺工具）
        → ④ 预订（OTA/酒店/门票）→ ⑤ 出行中（导航/导览/临时调整）→ ⑥ 分享复盘（社区）
```

- 阶段 ① 被小红书/抖音占据，阶段 ④ 被携程/飞猪/美团占据，阶段 ⑥ 被小红书占据。
- **阶段 ② 与 ③ 是「用户最烦、平台最不闭环」的地带**：用户在内容平台种草，然后跳到 OTA 查价，再回到备忘录/Excel 手工拼行程——这正是 WanderNote 的机会窗口。
- **阶段 ⑤ 是最大留存机会**：行程单在「出门当天」被打开的次数远高于生成当天，但目前多数产品在出行中就断供了。

#### 缺口诊断：为什么用户还在用备忘录

| 用户行为（现状） | 根因 | 产品机会 |
|---|---|---|
| 截图/收藏攻略 → 备忘录手打 | 攻略不可结构化、跨平台无法汇总 | **一键导入链接/截图 → 结构化行程** |
| Excel 排时间轴 | 生成结果不可直接编辑、改一处全乱 | **增量式局部重排（换景点/调时长）** |
| 出门截图保存行程 | 网络不稳、页面重、信息不聚合 | **离线行程卡 + 单屏时间轴** |
| 群里发截图给同伴 | 无协作编辑、无分享链接 | **可分享只读/协作行程页** |

## 3. 竞品分层地图

| 层级 | 代表产品 | 核心优势 | 与「行程规划」的关系 |
|---|---|---|---|
| A. 国内 OTA 巨头 | 携程、飞猪、同程、去哪儿、途牛 | 库存、价格、交易闭环 | AI 助手作为**入口搜索**，行程是交易的前置导流 |
| B. 内容社区 | 小红书、马蜂窝、穷游 | 内容种草、真实攻略 | 攻略结构化弱，行程工具是附属功能 |
| C. 独立行程工具 | 穷游行程助手、行程助手类小程序、圆周旅迹等 | 专注排行程、地图时间轴 | 功能最贴近本产品，但缺内容与交易 |
| D. AI 原生规划 | Layla、Mindtrip、Wanderlog(AI)、Roam Around、Trip Planner AI | 对话式生成、Agent 化 | **最直接的形态竞品** |
| E. 地图/系统厂商 | 高德、百度、Google Maps、Apple 地图 | 导航、POI 准确度 | 提供「路书/收藏点」能力，正在补 AI 规划 |

### 3.1 核心交互对比矩阵（重构靶心）

| 产品 | 冷启动输入 | 到第一版行程 | 生成耗时 | 可对话修改 | 可下单 | 协作 | 离线/行中 | 可信度机制 |
|---|---|---|---|---|---|---|---|---|
| **WanderNote（现状）** | 6 项表单 + 4 题必答 | **5 屏 / 6+ 次点击** | 骨架秒级 → 详情数十秒 | 有（回到对话页） | 否 | 否 | 无（仅地图+导航跳转） | 景点 KB（**仅 10 条 seed**） |
| 马蜂窝 AI 路书 | 初填 + 1 轮选择题 | 2 步 | 未找到公开数据 | 有 | 否（导流） | 否 | 否 | 双模型交叉验证 + 6300 万 POI |
| 携程 Trip.Planner | 3 问（目的地/天数/风格） | 3 步 / 30 秒 | 约 30 秒 | 部分 | **是**（直连） | 否 | 是（App 内） | 营业时间与交通时长校验 |
| 飞猪问一问 | 对话 + 表单 | 2-3 步 | **1-2 分钟** | 弱（报错不自我纠正） | **是** | 否 | 是 | 弱（预算算不准） |
| Layla.ai | **纯对话**（四成跳过目的地搜索） | **1 步** | 未找到公开数据 | 有 | **是** | 否 | 未找到公开数据 | AI + 真人顾问兜底 |
| Mindtrip | 对话 + 地图点选 | 2-3 步 | 未找到公开数据 | 有 | 否（组织与跳转） | 否 | 是（移动端 on-trip） | 1000 万+ POI + 3 万专家 |
| Wanderlog | 建 trip → 逐个加点 | 3-5 步 | 未找到公开数据 | 手工编辑为主 | 否 | **是（实时多人）** | **是（离线）** | 依赖 Google Places |
| TripIt | **转发邮件** | **0 步** | 即时 | 弱 | 否 | 否 | 是（航班提醒） | 航司/邮件数据源 |
| Google Canvas | 一句话 | 1 步 | 流式 | **强（可改权衡 + 历史回溯）** | **是（agentic）** | 否 | 是（Maps） | **实时价格 + Maps 评论照片** |
| ChatGPT Apps | 一句话 | 1 步 | 流式 | 强 | **是（第三方履约）** | 否 | 否 | 依赖第三方 |

**读表结论**：
- 本项目在「**到第一版行程的步数**」和「**可信度机制**」上落后最多；
- 在「**骨架秒级返回**」上**领先**飞猪（1-2 分钟），是应当保留并放大的优势；
- 「可下单」行业主流是**自营库存或深链**，本项目短期应选**深链**，不做库存。

## 4. 国内竞品分析

> 数据口径提示：同一产品的「规模」在不同来源差异极大（单 App / App+小程序 / 全渠道），下表均标注口径与年份，不混用。

### 4.0 规模对照（先看格局）

| 产品 | 月活（2025-09，App+小程序） | 月活（2025-05，单 App） | AI 产品 |
|---|---|---|---|
| 同程旅行 | **2.85 亿**（行业第一，几乎全在微信小程序） | 406.7 万 | 程心 AI / DeepTrip |
| 携程 | 1.46 亿 | 7635.02 万 | 携程问道、Trip.Planner |
| 去哪儿 | 6763 万 | 3125.93 万 | 无独立品牌 |
| 飞猪 | 3892 万（支付宝小程序占 33.1%） | 1121.37 万 | 问一问 |
| 马蜂窝 | — | 870.78 万 | AI 小蚂 / AI 路书 |
| 途牛 | — | 618.31 万 | 小牛 |
| 高德 / 百度地图 | — | 6.76 亿 / 6.33 亿 | 路书 + AI 搜索 |

来源：[QuestMobile 秋季报告转引](https://wap.zhengguannews.cn/html/zgh/370790.html)、[网经社 2025-05 单 App 月活](https://caifuhao.eastmoney.com/news/20250627155615888453680)。

> **关键判断**：规模第一 ≠ AI 第一。同程的 2.85 亿靠微信小程序，AI 品牌心智远低于马蜂窝；而马蜂窝（单 App 870 万）把 AI 做到了「入口级 + 主动提问」，是本次调研中**与本产品最接近、也最值得对标**的形态。

### 4.1 携程（行程 / Trip.Planner / 问道 / 口碑榜）

| 维度 | 现状 |
|---|---|
| 定位 | 全品类一站式预订，25-40 岁 + 商旅混合 |
| 交互路径 | 问道＝对话式；**Trip.Planner＝纯表单 3 步**（目的地→天数→风格），30 秒出日行程，自动校验营业时间与交通时长、地图呈路线 |
| 拿结果步数 | **约 3 步 / 30 秒** |
| AI | 问道 2023 年发布，2025 年接入 DeepSeek 且**用户可自主开关** |
| 商业化 | 行程内嵌门票/机票/酒店直连购买；口碑榜导流 |
| 口碑 | 2024-10 实测翻车：5 天行程只排到第 3 天、追问后重复推同一行程、丢失「上海中山公园」上下文推荐全国同名酒店、口碑榜被质疑人工干预 |
| 规模 | App+小程序 1.46 亿（2025-09）；2024 年净利 171 亿元 |

来源：[Trip.Planner 官方新闻稿](https://tw.trip.com/newsroom/trip-planner/)、[闻旅派 2024-10](http://www.wenlvpai.com/78422.html)。

**启示**：携程证明「少提问 + 快速出结果」可行（3 问 30 秒），但它自己也没解决「**行程排不满**」和「**多轮丢上下文**」——这恰是 WanderNote 已用两阶段 + 上下文持久化做对的地方。

### 4.2 飞猪（AI 问一问）

| 维度 | 现状 |
|---|---|
| 交互路径 | 对话+表单 → **表格化行程**（景点亮点与排名、交通方式与时长、酒店评分）→ 改预算重生成 → 页内一键预订 |
| AI | 行程助手 / 交通顾问 / 酒店管家 / 攻略达人 **多智能体协同** |
| 商业化 | 行程即货架，一键预订 |
| 口碑 | 生成需 **1-2 分钟**偏慢；**总预算算不准**；**返回错误后不依据上下文自我纠正**；被评「本质是固定工作流，不是灵活 MCP 调用」 |
| 规模 | App+小程序 3892 万（2025-09），其中支付宝小程序占流量 33.1% |

来源：[新华财经 2025-05-01](https://m.cnfin.com/hg-lb//zixun/20250501/4227088_1.html)。

**启示**：① 生成慢（1-2 分钟）是不可接受的——本项目「秒级骨架 + 后续细化」在体验上更优，应作为核心卖点保留并前移；② 「预算算不准」说明**预算必须是可校验的确定性计算**，不能让 LLM 直接编总价；③ 「报错不自我纠正」＝必须有重试/局部重算机制。

### 4.3 同程旅行（程心 AI / DeepTrip）

| 维度 | 现状 |
|---|---|
| 定位 | 下沉市场 + 微信生态，注册用户 87% 来自非一线城市 |
| AI | 程心 AI 融合 DeepSeek，首批 210 万用户体验；DeepTrip.com 支持 9 语言，主攻入境游 |
| 商业化 | 票务 + 住宿（2024 年交通票务收入 72.29 亿、住宿 46.68 亿） |
| 规模 | App+小程序 2.85 亿（2025-09，全渠道第一）；2024 年收入 173.41 亿、年付费用户 2.38 亿 |

来源：[央广网 2025-03](https://tech.cnr.cn/techph/20250326/t20250326_527113463.shtml)、[澎湃](https://m.thepaper.cn/newsDetail_forward_30446861)。

**启示**：小程序端才是国内行程类产品的真实主战场——本项目已用 UniApp 覆盖 H5/小程序/App，**分销与触达路径是通的**，重构不必动技术底座。

### 4.4 马蜂窝（AI 小蚂 / AI 路书）—— 最值得对标的对手

| 维度 | 现状 |
|---|---|
| 定位 | 攻略社区起家的年轻自由行决策入口，1.3 亿核心用户 |
| 入口位置 | **APP 首页搜索栏 + 目的地 POI 页**（不是独立功能页） |
| AI 小蚂 | 2025-04-28 上线，**DeepSeek 全量接入 + 自研垂直精调模型双模型交叉验证**（精调模型当「质检员」压制幻觉） |
| AI 路书 | 2025-07-11 开放，**「主动提问 → 需求校准 → 精准生成」**，用**选择题**反问（"是否避开台阶多的景点""餐饮人均预算"），输出含行程/住宿/交通/景点/美食/购物/预算/贴士的完整方案 + 目录跳转 |
| 拿结果步数 | **约 2 步**（初填 + 1 轮反问） |
| 数据资产 | 8000 万结构化旅游数据、**6300 万 POI**、6 万+ 目的地；2025 年底累计生成 131.5 万份攻略、覆盖 55 国 416 城、省时 471 万小时、代订餐厅 16,631 家 |
| 商业化 | 目的地营销（G/B 端）、主理人活动、研学、自驾共创、OTA 导流 |

来源：[TechWeb 2025-04-28](https://m.techweb.com.cn/article/2025-04-28/2960134.shtml)、[新浪财经 2025-07-11](https://finance.sina.com.cn/jjxw/2025-07-11/doc-inffawii2744175.shtml)、[北京日报 2024-09（1.3 亿核心用户 / 6300 万 POI）](https://finance.sina.cn/2024-09-29/detail-incqumnh0521343.d.html)。

**启示（三条可直接抄的作业）**
1. **AI 入口必须在首页搜索框**，不在「+ 创建行程」按钮里。
2. **提问方式用选择题 + 可跳过**，而不是一堆输入控件；反问 ≤1 轮。
3. **双模型交叉验证**是压制幻觉的低成本手段；本项目的对应物应为「**KB 命中校验 + 结构化输出 + 不确定即标注**」。

### 4.5 小红书 / 抖音（前端入口）

| 维度 | 现状 |
|---|---|
| 小红书 | 旅行内容 **1 亿月活用户、16 亿次搜索**；**只做前端不做行程单**——收藏夹 ≠ 行程 |
| 抖音 | 第一种草渠道中短视频占 32.6%；2025 年酒旅团购订单 +42%、酒店民宿订单 +63% |
| 最大痛点 | 收藏一堆笔记视频「**变不成行程**」 |

来源：[抖音生活服务 2025 文旅数据报告](https://www.news.cn/digital/20251229/ab5acbea6cbe454f888d100216722369/c.html)、[环球旅讯研究院 2026-05](https://www1.traveldaily.cn/article/189920)。

**启示**：内容平台**不会**做行程编排（不是它们的商业模式）。「**把收藏变成行程**」是本产品最高性价比的切入点——已有 `plan/import.vue`（链接导入）应升级为「链接 / 截图 → 结构化行程」，直接承接小红书场景。

### 5.3 海外赛道五大趋势

1. **从「生成行程」转向「可执行的预订闭环」**：生成能力已商品化——「生成一份行程本身越来越难构成长期壁垒，真正决定商业化的是实时库存、动态价格、支付、会员体系、售后履约和稳定流量」，而这些主要掌握在 OTA 手里。（[环球旅讯 2026](https://www1.traveldaily.cn/article/190495)）
2. **从「一个全能助手」转向「多垂直 Agent 协同」**：Expedia 收购 Layla 后的架构重构是最明确证据（2026）。
3. **从纯 AI 转向「AI + 真人」**：Layla 用真人顾问承接高客单复杂行程，线索转化提升 5 倍（2026）。
4. **从 B2C 工具转向 B2B2C**：Mindtrip 做目的地营销与酒店工具、GuideGeek 卖给旅游局。Skift 创始人 Rafat Ali：过去十年消费级旅游创业公司只有三种结局——**转 B2B、被巨头连人带技术收购、或关门**（2026）。
5. **流量入口位移**：Accenture 2025 消费者脉搏调查——**80% 旅客已用生成式 AI 工具**，对活跃 GenAI 用户而言 **GenAI 已是旅行发现第一入口，超过社媒与 OTA**（[Travolution 转述](https://www.travolution.com/news/gen-ai-is-becoming-a-top-source-for-travel-discovery/)）。

### 5.4 三大公认痛点（带公开数据）

| # | 痛点 | 最硬证据 |
|---|---|---|
| 1 | **幻觉与不可执行（feasibility / rationality）** | ACL 2025 Findings 的 **TripTailor** 基准：基于 **50 万+ 真实 POI 与近 4000 条真实行程**评估，**最先进 LLM 生成的行程中不到 10% 达到人类水平**，论文点名的挑战正是「可行性、合理性、个性化」（[TripTailor, ACL Findings 2025](https://aclanthology.org/2025.findings-acl.503/)） |
| 2 | **规划与下单断层（trust gap）** | Accenture 2025：**93%** 活跃 GenAI 用户已用或愿用 GenAI 辅助购买决策，**78%** 愿用 AI 购物助手，**57%** 想要能跨品牌自主完成任务的 AI 助手——需求存在，但跨品牌 Agent 的授权与履约仍未落地 |
| 3 | **无法修改 / 不可控** | Google Canvas 2025-11 大改的核心卖点就是「可追问、可改权衡、可暂停后回来编辑、有历史记录」——**「能编辑」被当作卖点而非默认能力**，反向证明修改能力此前普遍缺失；Skift 用「**Travel Slop（旅行垃圾内容）**」描述 AI 批量产出的低质行程（[Skift 2026](https://skift.com/2026/01/02/welcome-travel-slop-era/)） |

### 5.5 海外用户最在意什么（按证据强度排序）

1. **可执行性 / 可信度**：不到 10% 的 AI 行程达人类水平（TripTailor 2025）。
2. **真实价格与省钱**：Google Canvas 的卖点即接入实时航班与酒店价格、按预算筛选；Flight Deals 定位是「一句模糊描述找最便宜的 getaway」（2025）。
3. **可修改、可控**：Canvas 把「反复追问 + 编辑 + 历史回溯」作为核心交互；**86%** 旅客希望自己塑造体验（Accenture 2025）。
4. **少输入、少决策负担**：Accenture 把 GenAI 当期价值定义为「**解决选择与决策过载**」；Layla 四成用户跳过目的地搜索直接对话发起（2026）。

### 5.6 对 WanderNote 的三条硬结论

1. **不要在「生成行程」上竞争**——已被大模型商品化，长期壁垒在实时库存、价格、支付与履约。
2. **编辑与可执行性优先于生成质量**——可修改、可校验的行程比更漂亮的行程文本更有留存价值（对应本项目 P0「局部重排」与「信息可信化」）。
3. **对标对象不是 ChatGPT，而是 Layla/Wanderlog 的「混合模式」**——Layla 的「AI 初稿 + 人工兜底」与 Wanderlog 的「协作 + 地图时间轴 + 离线」，恰好对应本项目最缺的两块能力；同时**不必自建交易**，用深链跳转 OTA/地图即可回避重资产。

Wanderlog 用户数与融资额、Mindtrip 用户数、Roam Around 与 Trip Planner AI 的用户数/定价、Curiosio/Vacay 规模与定价、Booking.com AI Trip Planner 与 Google Canvas 的用户评价、Layla/Mindtrip 应用商店评论原文——均因反爬（403/付费墙/强制重定向）**未能取得，未做估算**。若需要，建议改用付费数据源（Sensor Tower、data.ai、Similarweb）。

### 6.6 AI 旅游助手接受度与顾虑

| 指标 | 数据 |

| 画像反转 | AI 规划用户中 80 后+90 后占 **73%**，70 后及更年长占 **26%**——**AI 旅行助手并非年轻人专属** |

来源：[Booking.com 全球 AI 态度报告 2025（中国大陆样本 2018 人）](https://news.booking.com/zh-chs/期待与审慎并存-：Booking-.com缤客首次发布全球ai态度报告/)、[环球旅讯研究院 2026-05](https://www1.traveldaily.cn/article/189920)、[马蜂窝 2026-03](https://www.donews.com/news/detail/1/6452569.html)。

> - **42% 总是核查** → 每个景点/价格必须**可溯源、可点开验证**；无法确认的信息应显式标注「待确认」，这比编一个精确数字更赢得信任。
> - **画像反转** → 目标人群不应只写「年轻人」（`backend/AI文旅.md` 中写的是年轻用户），应扩展到 80/90 后家庭与商旅。
> - **12% 愿独立决策** → 「AI 生成 + 人工一键微调」的混合模式是正确姿势，不要做「一键全自动不可干预」。

### 6.7 小红书 / 抖音在决策中的作用

- 小红书：**超 80%** 出行者先到小红书做攻略；`#跟着兴趣去旅行` 话题浏览 **17 亿次**；00 后 **90.3%** 依赖小红书/抖音/B 站。
- 抖音：第一种草渠道中短视频占 **32.6%**；Z 世代冰雪信息渠道抖音 **72.64%**、小红书 59.75%，**线下旅行社仅 3.14%**。
- 结构分工：**抖音负责「动心」，小红书负责「安心」**——短视频感性触发，小红书承担攻略对比与路线筛选。

> **对 WanderNote 的含义**：导入能力的输入源应明确写成「**小红书链接 / 截图**」，而不是泛泛的「游记链接」；文案与分享海报也应适配小红书格式（竖版图 + 路线图）。

### 6.8 出行中（on-trip）需求

- 最高频 AI 场景：**翻译 54%、餐厅推荐 52%、导航 51%、活动推荐 50%**；行后修图 46%。
- **行为证据**：超半数中国内地行程规划者在旅途中**每天掏手机 6 次以上**确认预订、导航与后勤。
- 需求侧期待：53.5% 青年期待大数据实时调度景区服务资源，**46.6% 期待按个人喜好推荐路线**，**36.7% 期待智能景区导览**。
- 情绪价值：42.54% 的 00 后暑期出游为放松身心、逃离压力。
- 找厕所、记账、实时调整的独立行为占比：**未找到公开数据**。

来源：Booking.com 2025、[Klook 2026](https://quanzhou.wandaresorts.cn/newsdetail-829479.html)、[中国青年报 2025-05](https://k.sina.cn/article_1726918143_66eeadff02001pbyq.html)、第一财经 2025。

> **对 WanderNote 的含义**：出行中的第一需求是「**少掏手机、一屏看完**」，其次是导览。当前 `trip/detail.vue` 是「地图铺满 + 上拉框」，信息密度足够但**没有「今天」视图**（拿到的是整段行程，不是「现在该去哪」）。建议新增 `trip/today.vue` 单屏今日卡。

### 7.1 竞争空位（WanderNote 可以占的位置）

```
                 可信/可执行（真实价格、能出门用）
                              ▲
                              │
       携程/飞猪（可订，但行程排不满、广告重）
                              │        ★ 空位：可信 + 可改 + 秒级出结果的「编排层」
                              │
   内容种草 ◄─────────────────┼─────────────────► 行程编排
                              │
       小红书/抖音（种草强，无行程）   马蜂窝（AI 最完整，但仍偏内容）
                              │
                              ▼
                     能改/能带出门（灵活性、离线、导览）
```

**WanderNote 的差异化三角**：
1. **秒级骨架**（已有技术优势：两阶段 + 缓存，对比飞猪 1-2 分钟）；
2. **一句话/一链接进**（对比国内普遍的表单前置）；
3. **可改 + 可带出门**（补上行业最大缺陷 54.7%「缺乏灵活性」与行中断供）。

| F1 | 拿到第一份行程要跨 5 个界面 | 首页 → wizard → survey → chat → detail | 冷启动流失 |
| F2 | 表单问题过多且必答 | `survey.vue:149` 强制校验全部 `questions` | 用户被迫回答自己也不确定的问题（如出发地、精确预算） |
| F3 | 表单/问卷与对话信息重复 | wizard 已收「偏好」，survey 又问「最想体验什么」 | 重复劳动，用户感觉被反复盘问 |
| F4 | 偏好选项硬编码为重庆 | `surveyQuestions.ts:22` INTEREST_OPTIONS = 火锅美食/山城风光… | 非重庆目的地出现错误选项，专业度受损 |
| F5 | 生成需要两次触发 | wizard「智能规划」只进对话；真正生成在 chat「生成行程」 | 用户困惑「为什么还没开始生成」 |
| F6 | 登录墙前置 | `wizard.vue:479` `if (!checkLogin()) return` | 首次体验被中断 |
| F7 | 分享不可用 | `trip/detail.vue:721` 「分享功能开发中」 | 断掉自然传播与协作 |
| F8 | 探索 Tab 名实不符 | `coming/index.vue` = 社区内容流 | 缺失「目的地种草/灵感」入口，用户不知道能去哪 |
| F9 | 单一生成路径，无「一句话直达」 | 无自由文本入口接管全部参数 | 与行业主流体验差距明显 |
| F10 | 出行中能力缺失 | 无离线行程、无语音导览（`docs/F1语音导览操作方案.md` 仍是待办）、无天气、无记账、无可协作 | 生成即结束，无复访场景 |
| F11 | 知识库极薄，幻觉风险高 | `docs/F1语音导览操作方案.md` 现状盘点：景点数据仅 **10 条 seed**（肇庆 1 / 广州 2 / 桂林 1 / 重庆 2 / 成都 2 / 杭州 2），description 仅 20~50 字 | 未收录城市等于纯 LLM 常识输出，门票/开放时间易错，直接打击「可信」体验 |

### 8.3 差距结论（对标行业）

| 维度 | 行业领先做法 | 本项目 | 差距等级 |
|---|---|---|---|
| 冷启动输入 | 一句话/一张截图/一条链接 | 6 项表单 + 4 题必答 | 高 |
| 首次出结果触点 | 1 屏内完成 | 5 屏 + 2 次确认 | 高 |
| 修改成本 | 对话式局部替换、拖拽 | 编辑页改字段 | 高 |
| 可信度 | 真实 POI、价格、可预订、标注来源 | 景点 KB + LLM，无价格来源标注、无预订 | 高 |
| 出行中 | 离线、导航、导览、实时调整 | 仅地图 + 导航跳转 | 高 |
| 分享/协作 | 分享链接、多人协作 | 未实现 | 中 |
| 内容与灵感 | 种草流 → 一键成行程 | 探索即社区流 | 中 |
| 落地速度 | 秒级骨架 + 流式 | 轮询 2.5s / 两阶段 | 低（已做对） |

## 9. 重构方向建议

### 9.0 调研结论 → 重构原则（一一对应，避免拍脑袋）

| 调研结论 | 数据/证据 | 重构原则 |
|---|---|---|
| AI 入口 = 搜索框 | 马蜂窝、携程、飞猪 AI 均在首页搜索栏 | **首页搜索框即规划入口**；`+ 创建行程` 降级 |
| 决策临期化 | 58.3% 当天预订；近 3 成当天/提前 1 天出行 | **首屏 ≤10 秒出可用骨架**，禁止 1-2 分钟等待 |
| AI 表单前置是最大摩擦 | 竞品普遍 2-3 步出结果；本项目 6 步 | **冷启动 ≤2 步**，问卷可跳过 |
| AI 头号缺陷是「不灵活」 | 54.7% 行程缺乏灵活性 | **生成后局部重排 = P0**，不是编辑器功能 |
| 42% 用户总是核查 | Booking.com 2025 | **来源标注 + 「待确认」显式提示**，不编造精确值 |
| 协作是第一压力源 | 协调行程时间 75.8% | **分享 P0、协作 P1** |
| 行中每天掏手机 6+ 次 | Klook 2026；36.7% 期待智能导览 | **今日单屏 + 离线 + 导览 = P0/P1** |
| 收藏变不成行程 | 小红书 1 亿月活 / 16 亿次搜索，无行程工具 | **链接/截图导入作为获客入口** |
| 纯工具会死 | 蝉游记下线、穷游停更 | 不做纯编辑器，必须闭环到「出门用」 |
| AI 用户 73% 是 80/90 后 | 马蜂窝报告 | **修正目标人群描述**，UI 兼顾可读性 |

### 9.1 定位重述

> **一句话——「把想去哪儿，变成今天就能出发的行程，并且出门时用得上。」**
> 从「AI 行程生成器」升级为「**随身行程助手**」：规划期做减法，出行期做加法。

### 9.2 目标用户与核心场景（用户场景优先于功能清单）

| 场景 | 用户语言 | 产品必须做到 |
|---|---|---|
| S1 周末周边短途 | 「这周六想去肇庆，两个人，别太累」 | 一句话生成 → 单屏行程卡 → 直接出发 |
| S2 种草转化 | 「刷到这篇攻略不错」/ 截图 | 链接/截图导入 → 结构化行程 → 可编辑 |
| S3 长线多城 | 「7 天云南，昆明大理丽江」 | 跨城交通衔接 + 路线不绕 |
| S4 出行中 | 「现在去下一个点怎么走 / 这景点讲讲」 | 离线行程 + 导航 + 语音导览 |
| S5 同伴协作 | 「发给朋友一起看/一起改」 | 分享链接 + 协作编辑/投票 |

### 9.3 核心链路重设计（把 6 步压到 2 步）

**现状**
```
首页 → 表单(6项) → 问卷(4题必答) → 对话页 → 点生成 → 轮询 → 详情
```

**建议**
```
首页（一个大输入框）─── 一句话/截图/链接 ───► 秒级骨架（首屏直接出）
                                     │
                          ┌──────────┴───────────┐
                     追问 ≤2 个关键槽位        直接细化
                     （可跳过，跳过即默认值）
                                     │
                                  行程卡（可改 · 可分享 · 可出行）
```

要点：
1. **输入即规划**：wizard 与 survey 不再是必经流程，改为「对话中渐进补全」。表单页保留为高级入口（「我想精细设定」）。
2. **槽位兜底**：未提供的参数用**可拒绝的默认值**填充（如预算按城市均价推定），而不是阻断提交；已填值在对话中可随时改。
3. **首屏 3 秒出骨架**：沿用现有 `frame/detail` 两阶段优势，把「骨架」直接渲染成可交互列表（不是等详情）。
4. **一键生成**：wizard 的「智能规划」应直接触发 `generatePlan`，不要中转对话页。
5. **登录后置**：允许游客完成 1 次生成，在「保存/分享」时才要求登录。
6. **问卷改造**：`INTEREST_OPTIONS` 按目的地动态生成（从 `AttractionKB` 标签派生），且**全部可跳过**。
7. **探索 Tab 换成「灵感」**：目的地卡片（季节/热度/主题）→ 点进去直接「用这个生成行程」，形成种草 → 规划闭环。

### 9.4 功能优先级（P0/P1/P2）

| 优先级 | 功能 | 理由 | 主要改动 |
|---|---|---|---|
| P0 | 一句话生成（对话即入口，首页搜索框接管） | 消除 F1/F2/F5；对标竞品 2-3 步出结果 | `ai/chat.vue` 支持无 `currentTrip` 冷启动；`buildBaseInfo` 允许缺省；新增自由文本解析 |
| P0 | 生成结果可局部修改（换一个 / 缩短时长 / 重排当天） | **行业第一大缺陷 54.7%** | `trip/edit.vue` 增加局部重排 → 命中 Agent 局部重算（不整单重生成） |
| P0 | 行程分享（链接/海报） | 传播 + 协作基础，且是已承诺功能 | `trip/detail.vue` 分享落地；后端分享 token |
| P0 | 今日模式（单屏 + 离线缓存 + 导航深链） | 行中每天掏手机 6+ 次；生成即结束=无复访 | 新增 `pages/trip/today.vue`；本地缓存行程 JSON |
| P0 | 信息可信化（来源标注 + 待确认标记 + 预算确定性计算） | 42% 用户总是核查；飞猪「预算算不准」翻车 | 景点/价格带来源字段；预算改为结构化求和而非 LLM 编数字 |
| P1 | 动态偏好问卷 + 对话内嵌选择题 + 可跳过 | 修 F2/F4；对标马蜂窝 AI 路书 | `surveyQuestions.ts` 由城市 KB 派生；评分制非必答 |
| P1 | 灵感/探索页 | 修 F8；对标「不知道去哪也能推」 | `coming/index.vue` 改版为目的地灵感流 |
| P1 | 截图/链接导入增强（小红书链接、笔记截图） | 承接种草；圆周旅迹已验证的需求 | 现有 `plan/import.vue` 扩展 OCR + 链接解析 |
| P1 | 语音导览 | 已在路线图；36.7% 期待智能导览 | 复用 `docs/F1语音导览操作方案.md`，TTS + 缓存 |
| P2 | 协作编辑/投票 | 协作是第一压力源，但实现成本高 | 成员权限模型 |
| P2 | 天气 / 记账 / 打卡 | 提升出行中黏性 | 第三方 API |
| P2 | 多城路径优化 | 长线场景 | `frame` 增加跨城段 |

### 9.5 度量指标（重构后必须可验证）

| 指标 | 现状基线 | 目标 |
|---|---|---|
| 首页 → 首份行程转化率 | 需埋点采集（当前无） | ≥ 35% |
| 首份行程耗时（点击→可见骨架） | 需埋点 | ≤ 10 秒 |
| 冷启动交互步数 | 6 步 | ≤ 2 步 |
| 生成后修改率 | 需埋点 | ≥ 25%（代表行程被当真） |
| 出行当日行程打开率 | 需埋点 | ≥ 20% |
| 分享率 | 0（未实现） | ≥ 5% |

> 建议在重构同时上线埋点：`plan_start / plan_generated / plan_edited / trip_opened_ontrip / trip_shared`。

## 10. 风险与不做什么

| 风险 | 应对 |
|---|---|
| 一句话生成的结果质量下降（槽位缺失导致幻觉） | 结构化输出 + KB 检索 + 「信息不足时主动追问 ≤2 个关键槽位」策略 |
| 完全去掉表单导致部分精细化用户不满 | 保留「精细设定」入口，不做强制 |
| 可预订能力超出当前资源 | 不做自建交易，改为**跳转 OTA/地图**（「去携程看价」「导航过去」） |
| 语音导览版权与准确性 | 讲解稿需标注来源，避免编造史实 |

**明确不做**：自建库存与支付、跟团/包价产品、UGC 内容运营重投入（社区保持轻量）。
