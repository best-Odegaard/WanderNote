# F1 AI 语音导览 · 操作方案

| # | 决策点 | 默认选择 | 备选 | 影响范围 |
|---|---|---|---|---|
| D1 | 语音合成 TTS | **edge-tts**（免费、无需 key、中文音质自然；agent 为 Python，加依赖即用），做成 `TTSProvider` 适配层 | 阿里云百炼 TTS（与现有 LLM 同 MAAS_API_KEY，更稳但需 key 开通且按量付费）；纯文字版（不合成） | §4 / §5.4 |
| D2 | 生成时机 | **详情页访问自动触发**（幂等：无讲解且非生成中 → 自动生成，前端轮询 2.5s） | 仅按钮手动触发；admin 预生成全量 | §6.3 |
| D3 | I 期范围 | **仅景点详情页讲解**（手动起播 + 段间连播） | 行程节点按顺序连播（+50% 工作量，留 II 期） | §9 |
| D4 | 管理端形态 | **独立"讲解管理"页**，挂"内容管理"分组，与景点管理平级 | 嵌在景点管理行内 | §7 |

补充说明（技术约束，非可选项）：H5 浏览器自动播放策略要求播放必须由用户手势触发，播放器页**采用"进入页面 → 用户点开始播放"**交互，点卡片跳页后直接自动起播可能被浏览器拦截。

## 1. 目标与范围

### 1.1 目标
把景点详情页的静态简介升级为"随行导游"：为每个景点生成 **4 段讲解稿**（开场引入 / 历史典故 / 看点导览 / 游玩贴士），逐段 TTS 合成音频并缓存到 COS，用户在详情页一键进入播放器连播；讲解内容入库，管理端可查看、禁用、重新生成。

### 1.2 分期范围
- **I 期（本期）**：`scenic_guide` 表 + agent 两个新路由（生成讲解稿 / 文本转语音）+ Java 异步任务编排（照抄 PlanTaskService 模式）+ COS 音频直传 + 详情页讲解卡片（自动触发 + 状态轮询）+ 播放器页 + admin 讲解管理页。
- **II 期（预留）**：行程节点按序连播、admin 讲解文本编辑、倍速/下载缓存。
- **III 期（预留）**：GPS 到达自动触发（定位权限 + 地理围栏）、多语言（英语等）、播放行为接入 E1 埋点统计（listen 事件）。

### 1.3 现状盘点（决定方案的关键事实）

| 项 | 现状 | 对方案的影响 |
|---|---|---|
| 景点数据 | 仅 **10 条** seed（肇庆 1/广州 2/桂林 1/重庆 2/成都 2/杭州 2，重庆洪崖洞与成都宽窄巷各重复 1 条）；description 仅 20~50 字 | 讲解稿主要靠 LLM 常识生成 → 必须在 prompt 约束"不编造具体价格/时间"；预生成全量成本可忽略（10 条 ≈ 2~4MB 音频）；**建议实施前在景点管理清理重复数据** |
| agent 结构 | `main.py` 105 行仅 2 路由（/api/chat、/api/plan）；ChatOpenAI 走阿里云百炼兼容通道；**无 requirements.txt**；无 CORS（Java 直连 127.0.0.1:8002，不涉及） | 新增路由与模块落点清晰；需补依赖清单与 `edge-tts` 依赖 |
| COS 上传 | 现有 `/user/private/file/cos/upload` 白名单仅 png/jpeg/mp4 + 图片内容校验 + 10 次/分限频 | **音频不走 HTTP 上传接口**，Java 用 gkv-server 已有的 COS Client Bean 内部直传（见 §5.4） |
| 异步任务先例 | `PlanTaskService`：ConcurrentHashMap + `Executors.newFixedThreadPool(4)` + 内存任务表 + status 轮询端点；前端轮询间隔 2.5s | 照抄该模式新建 GuideTaskService，不复用（PlanTaskService 与行程/AgentHttpUtil 强耦合） |
| 前端播放 | 全仓库**零 audio/InnerAudioContext 代码** | 播放器从零写，用 `uni.createInnerAudioContext()`（H5/小程序通用） |
| 页面与版本 | pages.json 22 页平铺结构；SQL 最大 V1.9；无任何 audio/guide 相关表 | 新增页加同结构条目；新表无命名冲突 |

## 2. 整体流程

```
用户打开景点详情页
   └─ GET /guide/{scenicId}
       ├─ 完成(2)   → 展示"播放"卡片（段落数/总时长）
       ├─ 生成中(1) → 展示进度，轮询任务状态
       ├─ 失败(3)   → 失败提示 + 重试按钮
       ├─ 禁用(4)   → 不显示入口
       └─ 未生成     → POST /guide/generate/{scenicId} 自动触发（幂等）

生成任务（GuideTaskService 内存任务，照抄 PlanTaskService）:
  1) agent /api/guide/generate（景点资料 → 4 段 {title,text}，LLM 结构化输出）
  2) 逐段 agent /api/tts（text → mp3 bytes）
  3) Java 直传 COS: audio/guide/{scenicId}/{seq}_{ts}.mp3 → 拿 URL
  4) 组 segments_json 落库 scenic_guide(status=2)；任一步失败 → status=3 + fail_reason

播放器页 pages/guide/player?scenicId=: 用户点"开始播放"→ 段间自动连播
管理端: 列表/查看全文/禁用启用/重新生成
```

## 3. 数据库变更

> 文件放置：新增 `backend/sql/V1.13__create_scenic_guide.sql`，**同步复制一份到 `deploy_v2/sql/`**。
> ⚠️ `deploy_v2/sql/` 缺 V1.7/V1.8（user_favorite、admin/feedback），若目标部署库从未执行过，需先补齐再执行新版本（与 E1 文档一致）。

```sql
CREATE TABLE scenic_guide (
  id            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  scenic_id     BIGINT       NOT NULL                COMMENT '景点id',
  city          VARCHAR(64)  DEFAULT NULL            COMMENT '景点城市(冗余,便于管理端筛选)',
  status        TINYINT      NOT NULL DEFAULT 1      COMMENT '1生成中/2完成/3失败/4禁用',
  segments_json TEXT         NULL COMMENT '[{"seq":1,"title":"...","text":"...","audioUrl":"...","durationSec":55}]',
  total_sec     INT          NOT NULL DEFAULT 0      COMMENT '总时长秒',
  fail_reason   VARCHAR(255) DEFAULT NULL            COMMENT '失败原因(agent错误信息截断)',
  create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_scenic (scenic_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='景点AI语音讲解';
```

- 无记录 = 未生成；`segments_json` 与 `trip_plan.day_plans` JSON 风格一致，MyBatis 按 String 读写；
- 段落规格：每段 **150~220 字**（约 40~60 秒），`durationSec = text 字数 / 4` 估算，`total_sec` 累加；
- 删除 = 物理删除讲解 + 保留 COS 文件即可（文件量小，I 期不做清理任务）。

### 4.2 路由契约

**① 生成讲解稿**
```
POST /api/guide/generate
Body: { "name":"七星岩", "city":"肇庆", "category":"自然风光", "description":"…",
        "openTime":"08:00-18:00", "price":"78", "address":"…" }
Resp 200: { "segments": [ {"seq":1,"title":"初见七星岩","text":"…150~220字…"}, … 共4段 ] }
Resp 500: { "detail": "错误信息" }
```
Prompt 硬约束（写进 `guide_service.py`，防幻觉关键）：
- 输出恰好 4 段：开场引入 / 历史典故 / 看点导览 / 游玩贴士；
- **只基于传入资料与公认常识**；资料未提供的价格、开放时间、数字**只做泛化描述（如"需购票入园"），禁止编造具体数值**；
- 每段 150~220 字、口语化、适合朗读，不要 markdown。

**② 文本转语音**
```
POST /api/tts
Body: { "text":"…", "voice":"zh-CN-XiaoxiaoNeural" }
Resp 200: audio/mpeg 二进制流
Resp 503: { "detail": "tts unavailable: …" }   // edge-tts 网络失败等，Java 转任务失败
```

### 5.2 GuideTaskService 规格（照抄 PlanTaskService 模式）

- `ConcurrentHashMap<String, Task>` + `Executors.newFixedThreadPool(4)`，内存态即可（任务结果落库，进程重启丢任务可接受——前端重进详情页重新触发）；
- 状态：`PROCESSING / DONE / ERROR / CANCELED`（可先不实现 cancel）；
- 任务执行：文本生成（1 次 agent 调用）→ 逐段 TTS（4 次调用，每次 ~2~5s，全程约 20~40s）→ COS 上传 → 落库；
- 失败：置 DB `status=3` + `fail_reason`（截断 255 字），task 状态 ERROR，前端显示重试；
- 防并发：Redis `guide:gen:{scenicId}` setnx TTL 5min；DB 状态为 1(生成中) 时重复触发直接返回现有 taskId。

### 5.3 GuideService 编排要点

- `get(scenicId)`：无记录 → status=0；失败/生成中 → 原样返回（含 fail_reason）；
- `generate(scenicId)`（幂等）：已完成 → 直接返回（不重新生成）；生成中 → 返回现有 taskId；否则建任务；
- 任务内组装 `segments_json`：`[{seq,title,text,audioUrl,durationSec}]`，`total_sec` 累加。

### 5.4 音频 COS 直传（关键：不动现有上传接口）

- 原因：现有 `/user/private/file/cos/upload` 白名单仅 png/jpeg/mp4 + 图片内容校验 + 10 次/分限频，不适合 Java 内部传音频；
- 实现：复用 gkv-server 的 `CosClientConfig` Client Bean，`putObject(bucket, "audio/guide/{scenicId}/{seq}_{ts}.mp3", bytes)`，返回 `https://{bucket}.cos.{region}.myqcloud.com/{key}` 完整 URL；
- 类型：`audio/mpeg`；每段约 100~300KB，全量 10 景点约 2~4MB，成本可忽略；
- 影响面：纯新增，不改动原图片上传链路。

### 5.5 接口契约（统一 `Result<T>`，分页 `PageResult<T>`）

**① 查询讲解**（登录）
```
GET /guide/{scenicId}
Resp: Result<GuideVO>
  status: 0未生成/1生成中/2完成/3失败/4禁用；2 时携带 segments 与 totalSec
```

**② 触发生成**（登录，幂等）
```
POST /guide/generate/{scenicId}
Resp: Result<ScenicGuideTaskVO>   // {taskId, status}；已完成时直接返回 DONE，不再生成
```

**③ 任务轮询**（登录）
```
GET /guide/task/{taskId}
Resp: Result<ScenicGuideTaskVO>   // {taskId, status:PROCESSING/DONE/ERROR, elapsedSec, errorMsg}
```

**④ 管理端列表**（admin）
```
GET /admin/guide/page?pageNum=1&pageSize=10&status=&keyword=
Resp: Result<PageResult<AdminGuideVO>>
```

**⑤ 查看全文**（admin，分段落展示文本）
```
GET /admin/guide/{id}
Resp: Result<GuideVO>
```

**⑥ 禁用/启用**（admin）
```
PUT /admin/guide/status/{id}/{toStatus}   // toStatus ∈ 2(启用)/4(禁用)
Resp: Result<Void>
```

**⑦ 重新生成**（admin，对 2/3/4 状态景点）
```
POST /admin/guide/regenerate/{id}
Resp: Result<ScenicGuideTaskVO>   // 复用 ③ 轮询
```

## 10. 风险与备注

- **edge-tts 网络依赖**（最大风险）：依赖微软接口，大陆网络偶发不通 → 已设计"任务失败可重试 + 音频落 COS 后只播缓存"；若演示环境不稳定，切 D1 备选（阿里云百炼 TTS，只换 `tts_service.py`/TTSProvider 实现，编排零改动）；
- **LLM 幻觉**：seed description 仅 20~50 字，讲解稿主要靠模型常识 → prompt 硬约束"不编造具体数值" + admin 可查看全文人工把关 + 可禁用兜底；
- **数据质量**：seed 中重庆洪崖洞、成都宽窄巷各重复 1 条 → 建议预生成前在景点管理清理，避免讲解撞车；
- **音频成本**：单景点约 1~2MB，10 景点总量可忽略；后续景点增多再考虑 COS 生命周期规则（可选，本期不做）；
- **与 E1 的关系**：两方案独立可实施、可共存；SQL 版本已错开（E1: V1.10~1.12，本文档: V1.13），行为上报按 §9.4 二期对接。
