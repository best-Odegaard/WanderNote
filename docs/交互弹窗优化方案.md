# 交互弹窗与轻反馈优化方案

> 范围：`geek012-flash/frontend`（uni-app 3 + Vue3 + Pinia，三端：H5 / App / 微信小程序）
> 原则：**只改表现层，不动业务逻辑**——所有调用点的参数、回调、触发条件、时序、跳转目标原样保留，仅把渲染实现从平台原生 API 换成与主题令牌一致的自定义弹层。
> 关联背景：commit `96c67af` 已完成「亮色大圆角玻璃拟态 + 六级字号令牌化」主题改造，但交互弹窗未跟上，仍是平台默认样式。

## 二、细节问题分析

1. **风格割裂，主题改造半成品**：原生 toast 在 H5 是黑色小胶囊、App 是系统样式、小程序是微信绿按钮，与「薄荷绿大圆角玻璃拟态」完全两个语言；深色模式下原生弹层尤其突兀。
2. **确认弹窗不统一**：三处删除确认文案各不相同；`confirmColor` 一处写 `#E64340`、两处写 `#e64340`（大小写不一致，且硬编码绕过了已有令牌 `var(--danger)`）；标题全是「提示」，无危险操作语义。
3. **Toast 无语义分级**：成功/失败/中性都是黑底白字；长文案会被截断（如 chat.vue:620「行程已生成，但保存失败，请稍后在详情页重试保存」22 字）；时长靠手写 `duration` 猜。
4. **后端错误原文直出**：request.ts 把 `body.msg` 直接弹给用户，可能出现长句、英文、技术串，无兜底美化。
5. **反馈噪音**：点赞/收藏/关注/取关全部弹 toast，属于高频低价值打扰；「功能开发中」「分享功能开发中」是死路提示，没有后续动作。
6. **文案散落硬编码**：「请先登录」4 处、「请先登录后创建行程」3 处，后续改文案要全文检索。
7. **自定义遮罩只有入场没有退场动画**（`v-if` 直接卸载，弹窗「硬消失」）；z-index 各写各的（100 / 300 / 1000 并存），弹窗套弹窗时层级不可控；H5 上遮罩打开时背后页面仍可滚动。
8. **`showModal({editable:true})`**（survey 手动添加需求）在 H5 退化为浏览器 prompt 风格，是三端差异最大的一个点。

## 三、方案设计

### 3.1 总体策略：同名函数替换（shadow API）

新增 `src/utils/feedback.ts`，导出与 `uni` **完全同名同签名**的函数：

```ts
showToast(options)      // 签名与 uni.showToast 一致
showModal(options)      // success 回调仍收到 { confirm, cancel, content }
showLoading(options) / hideLoading() / hideToast()
showActionSheet(options) // success 回调仍收到 { tapIndex }
```

页面与工具层把 `uni.showToast(...)` 机械替换为 `showToast(...)`（import 自 feedback）。**调用参数、if 判断、setTimeout 时序、navigate 目标一律不动**，diff 里只应出现 import 行和调用前缀的变化。

渲染层：`App.vue` 挂载全局 `<AppFeedback />`（fixed 全屏容器），由 `useFeedbackStore`（仅存弹层 UI 状态：toast 队列、modal 栈、loading 计数）驱动。该 store 不碰任何业务 store，属于纯展示状态。

三端兼容：自定义弹层是纯 view 渲染，H5/App/小程序行为完全一致，不再受平台差异影响。feedback.ts 内部保留一行切回 `uni.*` 的降级开关，应急可秒回退。

### 3.2 组件与视觉规范（全部吃 theme.scss 已有令牌，不新增色值）

| 组件 | 规格 |
|---|---|
| AppToast | 玻璃胶囊：`var(--glass-bg-strong)` + `backdrop-filter: blur(var(--glass-blur))` + 玻璃描边；三态图标（成功=品牌绿 ✓ / 失败=危险红 / 中性）；超过 14 字自动换行不截断；时长按字数自适应 1800–3000ms；深色模式自动适配 |
| AppConfirm（替代 showModal） | 居中玻璃卡片，圆角 `$radius-2xl`；标题 `--fs-heading`、正文 `--fs-body`；危险操作（删除）红色图标 + `var(--danger)` 确认按钮，`confirmColor` 透传；`showCancel:false` 时单按钮；`editable:true` 时渲染内嵌输入框（替代 survey 的 prompt 式弹窗）；**点击遮罩不关闭、Android 物理返回不关闭——与 uni.showModal 默认行为保持一致**（这是不动逻辑的关键） |
| AppActionSheet | 底部动作面板，三项带图标（复制 / 高德 / 腾讯），独立取消行，圆角 `$radius-xl` |
| AppLoading | 居中玻璃转圈 + 文案；request.ts 的 `loadingCount` 与 `store/app.ts` 的 showLoading/hideLoading 合并为单一计数（后者改为委托，导出签名不变，防止隐藏调用方） |

**统一 z-index 层级表**（新增弹层固定值，页面内旧遮罩暂不动）：
toast 2000 / confirm·actionSheet 3000 / loading 4000 —— 保证「弹窗套弹窗」（如删除确认后弹成功 toast）层级永远正确。

**动效**：入场 `scale 0.96→1 + opacity`（`$ease-spring`，240ms）；退场 150ms 淡出。同时给现有 6 类自定义遮罩补退场动画（仅包一层 transition，不动结构）。

### 3.3 文案治理（保守）

- 建立 `FEEDBACK_TEXT` 常量表，仅做**重复串合并**（「请先登录」等），不改动任何用户可见措辞——措辞优化单独列为 P2 可选项，需产品确认后再做。
- request.ts 错误提示加兜底：超长（>20 字）或含英文技术串时降级为「操作失败，请重试」，原文只进 console。

## 五、不动逻辑的保障措施

1. **替换粒度**：只改「谁渲染」，不改「何时渲染、渲染什么、之后干嘛」。所有 `success/fail/complete` 回调、`res.confirm` 判断、`setTimeout + switchTab/navigateBack` 时序原样保留。
2. **验收**：`npm run type-check` 全绿；逐文件 `git diff` review，预期每个文件只有 import 行 + 调用前缀 `uni.`  removal 两类变化；`ui_smoke` 系列脚本回归。
3. **回滚**：整体一个 commit，`git revert` 即回到原生弹层；feedback.ts 内留 `USE_NATIVE_FEEDBACK` 开关可运行时降级。
4. **边界确认**：AppConfirm 的遮罩点击、返回键行为、`editable` 内容回传（`res.content`）三项与 `uni.showModal` 逐一对齐，避免行为差异渗入业务。
